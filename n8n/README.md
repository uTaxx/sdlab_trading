# n8n 워크플로 안에 있는 코드

n8n은 SaaS라 코드가 저장소 밖에 산다. 그런데 이 코드가 화면과 칸 이름을
맞춰야 하고, 한 글자만 달라도 화면의 그 칸이 조용히 빈다.

**여기 있는 것은 사본이다.** 진짜로 도는 것은 n8n에 있다. 고칠 때는 두 곳을
같이 고친다. 테스트가 사본과 화면의 칸 이름이 맞는지만 본다. 사본과 n8n이
어긋난 것은 테스트가 못 잡는다.

| 파일 | n8n 워크플로 | 노드 |
|---|---|---|
| `대시보드자료_화면모양으로.js` | 무원406 대시보드 자료 (`wj3pZvpHJPekTaoI`) | 화면 모양으로 |
| `telegram_receive.ts` | AutoTrading_Telegram (`7tSSThvQIsLiIsLk`) | 확인 필요 |

## 왜 사본을 두나

2026-09-01에 이 노드를 고치다 한글이 여러 개 깨졌다. `잰때`가 `재때`로,
`사고팜`이 `사고팈`으로 바뀌었다. 둘 다 화면이 읽는 칸 이름이라, 회차
표와 최근 주문 표가 빈 채로 떴다. n8n 화면에서는 코드가 멀쩡해 보이고
워크플로도 초록불이라 어디가 틀렸는지 안 보였다.

사본이 있으면 고치기 전과 후를 diff로 볼 수 있다.

## 지금 어긋나 있는 것 (2026-09-01)

`대시보드자료_화면모양으로.js`의 전략추적 갈래 주석 한 줄이 n8n과 다르다.
사본은 `못한까닭`, n8n은 `못잰까닭`으로 적혀 있다. 시트의 칸 이름을 바꾸면서
사본만 따라갔다.

주석이라 동작에는 영향이 없다. 이 파일을 다음에 n8n으로 올릴 때 같이
맞추면 된다.

`AutoTrading_Schedule`(`t2t8DmJ9d7yB4g4U`)의 `전략 검토 부르기` 노드 설명에
"상태 DB는 읽기만 한다"가 남아 있다. 그림자 추적이 붙으면서 이제 쓴다.
설명이라 동작에는 영향이 없지만, 사람이 읽고 판단하는 자리라 다음에 그
워크플로를 고칠 때 같이 고친다. 여기 적어 두는 이유는, 적어 두지 않으면 다음 사람이 diff에서
이 한 줄을 보고 무엇이 맞는지 판단할 근거가 없기 때문이다.
