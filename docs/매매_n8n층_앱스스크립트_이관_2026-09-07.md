# 매매의 n8n 층을 Apps Script로 옮기는 설계 (2026-09-07)

주인이 2026-09-07 오후에 회사 시스템과 매매 둘 다 Google Apps Script로 옮기기로
정했다. 단, 최종 연결은 전부 완성된 뒤에 하고 먼저 기반만 준비한다.

회사(LX) 쪽 설계와 코드는 `uTaxx/muwon406`의 `docs/앱스스크립트_이관_설계_2026-09-07.md`와
`apps-script/lxgroup`에 있다. 그 문서에 Apps Script에서 무엇이 되고 안 되는지
확인한 것(§2), 배포 방식(§7), 주인이 해야 하는 인증(§6)이 적혀 있다. 여기서는
매매 쪽만 적는다.

## 1. 매매 쪽 설계
주인이 회사 시스템과 매매 둘 다 Apps Script로 옮기기로 정했다. 단, 최종
연결은 전부 완성된 뒤에 하고 먼저 기반만 준비한다.

### 1-1. 무엇을 옮기나

매매의 파이썬 엔진은 옮기지 않는다. pandas와 증권사 주문 코드는 Apps
Script에서 실행할 수 없다. 옮기는 것은 n8n이 맡던 층 넷이다.

| n8n 워크플로 | 하는 일 | Apps Script |
|---|---|---|
| AutoTrading_Schedule | 정해진 시각에 GitHub Actions 10개를 부름 | `trading/src/시계.js` |
| AutoTrading_Telegram | 텔레그램 버튼·명령을 `telegram-n8n.yml`로 넘김 | `trading/src/텔레그램.js` |
| AutoTrading_계좌조회 | 화면의 계좌 조회(`muwon-balance`) | `trading/src/계좌.js` |
| 무원406 대시보드 자료 | 화면 자료 창구(`sdlab`), 노드 40개 | `trading/src/자료.js` (자리만) |

### 1-2. 시각을 어떻게 맞추나

앞 절에서 "매매는 시각이 중요해 n8n에 둔다"고 했던 까닭이 이것이다. Apps
Script의 시간 트리거는 정확한 시각을 보장하지 않는다. 그래서 두 가지를 한다.

- 1분마다 트리거를 받아 시간표에서 지금 분에 해당하는 일을 찾아 부른다.
  트리거가 늦게 와도 3분 안이면 부르고, 그것을 넘기면 놓친 것으로 적고
  부르지 않는다. 09:05 매수를 09:40에 부르면 승인한 값과 다른 값에 산다.
- 관찰 모드로 먼저 올린다. 부르지 않고 "예정 09:05, 실제 09:05:07"만 시트
  `시계기록` 탭에 적는다. 한 주쯤 모아 늦는 정도를 본 뒤 넘어갈지 정한다.
  숫자를 보기 전에는 넘어가지 않는다.

1분 트리거는 하루 1,440번 실행된다. 한 번이 1초 안팎이라 하루 트리거 실행
시간을 20~25분 쓴다. 개인 계정 한도 90분 안이지만 회사 쪽 수집과 같은 계정
이면 합쳐서 본다. 매매와 회사가 다른 구글 계정이면 이 걱정이 없다.
**두 시스템이 같은 계정인지 확인하지 못했다.**

### 1-3. 텔레그램 웹훅은 마지막에 건다

텔레그램 봇의 웹훅을 Apps Script 주소로 바꾸는 순간 n8n의 텔레그램
트리거는 더 못 받는다. 그래서 `텔레그램웹훅걸기()`는 사람이 편집기에서
직접 실행할 때만 돈다. Apps Script는 요청 헤더를 못 읽어서 텔레그램의 비밀
헤더를 확인할 수 없고, 대신 웹훅 주소에 비밀값을 붙여 대조한다.

### 1-4. 화면 쪽에서 바뀌는 것

- `dashboard/app.js`의 `부르기()`가 HTTP 상태 401·403·404를 보고 있다. Apps
  Script는 늘 200이라 본문 `상태` 칸을 보도록 고친다. 회사 hub.html은 이미
  `ok:false`를 보고 있어 그대로다.
- Content-Type을 `text/plain`으로 바꾼다. 두 화면 모두다.
- n8n 계좌조회에는 시트를 못 읽었을 때 쓰는 옛 인증 키가 코드에 박혀
  있었다. 옮기지 않았다. 시트를 못 읽으면 거절한다.

### 1-5. 매매 쪽 옮기는 순서

| 단계 | 하는 것 | 사람이 할 일 |
|---|---|---|
| A | 프로젝트 만들기, 관찰 모드 시계 설치, 한 주 기록 | 권한 허용, 스크립트 속성 넣기, 편집기에서 `시계설치` 실행 |
| B | 계좌 조회 확인(증권사 모의투자로) | 없음 |
| C | 자료 창구 40노드 이식, 화면 `부르기()` 고치기 | main 합치기 |
| D | 시계기록을 보고 넘어갈지 결정 | 결정 |
| E | 같은 날에 n8n 시계 끄고 `CLOCK_MODE`를 실행으로 | 결정 |
| F | 텔레그램 웹훅 걸기, n8n 텔레그램 끄기 | 편집기에서 `텔레그램웹훅걸기` 실행 |

E와 F는 같은 계좌를 두 프로그램이 부르지 않게 하는 자리다. n8n을 끄지 않고
Apps Script를 실행으로 두면 08:30 후보와 09:05 매수가 두 번 나간다.

## 2. 기반 단계에서 만든 것 (2026-09-07)

`apps-script/trading`에 있다. 설명은 `apps-script/README.md`다.

- 시간표 10개(n8n과 같은 시각·입력), 1분 트리거와 관찰 모드, GitHub
  workflow_dispatch 호출, 텔레그램 받기와 웹훅 걸기·풀기, 증권사 토큰 캐시와
  잔고 조회와 화면 모양(n8n 코드 그대로), 웹 앱 입구(동작 4개), 권한확인.
- 배포 워크플로 `apps-script-deploy.yml`(create·push·deploy). Node 시험 15개와
  파이썬 시험 10개.
- 매매 프로젝트는 주인이 직접 만들었고 스크립트 ID가 `.clasp.json`에 있다.
  clasp 로그인 비밀값이 들어오면 코드를 올린다. 아무것도 연결하지 않았다.
