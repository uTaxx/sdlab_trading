## 5. 구조 — 기초전략과 세부전략

매매를 사는 쪽과 파는 쪽으로 나누고, 각 쪽을 두 층으로 본다.

|  | 기초전략 (어떤 전략을 걸든 항상) | 세부전략 (지금 걸린 전략) |
|---|---|---|
| 매수 | 매수 스위치, 비중, 동시보유, 섹터당, 거래대금 문턱, 하루 손실 한도, 승인 필요 | 사는 전략 |
| 매도 | 매도 스위치, 손절선, 익절선, 보유 기간 상한 | 파는 전략 |

- 기초는 대시보드에서 바꾼다.
- 세부는 대시보드에서 **보기만** 된다. 바꾸려면 `switch-strategy.yml`을 돈다.
  전략을 바꾸는 것은 돈이 나가는 결정이라 화면에서 조용히 되게 두지 않았다.

### 0이 뜻을 가진 칸이 넷이다

| 칸 | 0의 뜻 |
|---|---|
| 익절선 | 끔 |
| 보유 기간 상한 | 전략이 정한 대로 |
| 섹터당 종목 수 | 제한 없음 |
| 거래대금 문턱 | 문턱 없음 |

나머지 칸은 0을 안 받는다.

### 파는 순서

손절 → 익절 → 보유 기간 → 세부전략의 매도 신호. 먼저 걸리는 것 하나로 팔린다.
판단은 `src/muwon/risk/exits.py`의 `evaluate_exit()`가 한다.
"며칠까지 들고 있나"는 같은 파일의 `보유상한()`이 낸다.

### 매수와 매도를 다른 전략으로 걸 수 있다

`src/muwon/strategy/split.py`의 `SplitStrategy`. 매수 신호는 매수 쪽에서만,
매도 신호는 매도 쪽에서만 나온다. 보유 기간 상한도 매도 쪽 것을 쓴다.
지금은 안 걸려 있다.

## 9. 반복해서 다시 알게 되는 것들

- **로컬 venv를 쓴다.** 시스템 `python3`에는 pandas가 없다.
  `/home/user/muwon406/.venv/bin/python`
- **대시보드는 브라우저로 확인한다.** 테스트와 ruff를 통과하고도 화면이 죽은
  적이 여러 번 있다. Playwright + `/opt/pw-browsers/chromium`.
  - 킬스위치 단추는 `confirm()`을 띄운다. headless에서 `page.on("dialog", ...)`로
    받지 않으면 거기서 멈춘다.
  - 폰 폭(390px)으로도 볼 것.
  - localStorage 열쇠는 `sdlab.연결`
- **GitHub Actions 실행 목록 응답은 토큰 한도를 넘는다.** `per_page`를 줘도
  무시한다. `actions_get`으로 하나씩 보거나 `status` 필터를 걸 것.
- **워크플로 아티팩트를 curl로 못 받는다.** 프록시가
  `productionresultssa*.blob.core.windows.net`을 막는다. 대신 `get_job_logs`로
  로그를 읽으면 스크립트 출력이 그대로 있다.
- **`workflow_dispatch`의 `type: boolean` 입력에 문자열을 넘기면 안 된다.**
  `"false"`가 참으로 읽혀 조용히 반대로 돈다. JSON 불리언을 넘길 것.
- **상태 DB를 고치는 워크플로는 전부 `state-write` 그룹이다.** DB가 파일
  하나라 겹치면 나중 것이 앞 것을 덮는다. `tests/test_workflow_locks.py`가 고정한다.
- **분봉은 그날 안에만 받을 수 있다.** 수집이 실패한 날은 그날 저녁에 손으로
  다시 돌리면 구제된다. 다음 날이면 없다.
- **유니버스 스냅샷은 주마다 바뀐다.** 같은 조건으로 다시 재도 숫자가 달라진다.
  성적표는 항상 한 실행에서 나온 숫자만 담을 것.
- **실험 워크플로의 `fill_timing` 기본값은 `close`다.** 성적표는 `open`으로
  잰 숫자다.
