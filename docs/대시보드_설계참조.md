# 대시보드 설계 참조 (Phase 8용)

사용자가 제시한 모바일 목업을 옮겨 적은 문서. **2026-08-18 구현 완료**.
아래 §7에 목업과 실제 화면의 차이와 그 이유를 적었다.

## 1. 전체 구조

두 화면짜리 모바일 앱 형태. 하단 탭 5개로 나뉜다.

```
┌────────────────────────────────────────┐
│  제목 (굵게)              🔔 ❓ ⚙️      │
│  부제 (연한 회색)                       │
├────────────────────────────────────────┤
│                                        │
│            (화면 내용)                  │
│                                        │
├────────────────────────────────────────┤
│  🏠      📈      📋      🔔      👤     │
│ 대시보드  전략    기록    알림    관리    │
└────────────────────────────────────────┘
```

- 알림 아이콘에는 **빨간 점(미확인 표시)**
- 현재 탭만 파란색, 나머지는 회색 아웃라인

## 4. 시각 언어

- **배경**: 아주 연한 회색, 카드는 흰색 + 둥근 모서리(16px 내외) + 옅은 그림자
- **아이콘 칩**: 48px 정도의 둥근 사각형, 파스텔 배경 + 진한 아이콘
  (보라=전략, 초록=연결/인증, 파랑=데이터/기록, 주황=시간, 분홍=비교, 청록=텔레그램)
- **상태 배지**: 알약 모양
  - 초록 = 정상/연결됨
  - 보라 = LIVE
  - 파랑 = 건수(3건, 128건)
  - 회색 = 시각(방금 전)
- **여백이 넉넉**하고 한 화면에 5~6줄. 지금 Streamlit 화면처럼 촘촘하지 않다.

## 5. 지금 화면과의 차이 (구현 시 판단할 것)

| 항목 | 지금 | 목업 |
|---|---|---|
| 구조 | 한 페이지에 expander 9개 세로 나열 | 탭 5개 + 요약 먼저 |
| 첫 화면 | 설정부터 보임 | **상태 요약 카드**부터 |
| 설정 | 본문에 섞여 있음 | `관리` 탭으로 분리 |
| 알림 | 없음 | 별도 탭 + 미확인 뱃지 |

## 6. 착수 전에 정해야 할 것

1. **"전략 3개 활성"**. 목업은 전략을 동시에 여럿 운용하는 것을 전제한다.
   지금은 활성 전략이 **하나**(`strategy.active_key`)다. 여러 전략을 동시에
   운용하려면 자본 배분·중복 진입·성과 귀속을 어떻게 할지부터 정해야 한다.
   화면보다 엔진 쪽 결정이다.
2. **하단 탭 바**. Streamlit에 기본 제공되는 위젯이 아니다. 상단 `st.tabs`로
   대체하거나 CSS를 직접 넣어야 한다. 목업 그대로는 공짜가 아니다.
3. **"오늘 손익 +1.8%"**. 지금은 평가금액만 저장한다. 일간 수익률을 화면에
   쓰려면 기준 시점(전일 종가 기준인지 당일 시가 기준인지)을 정해야 한다.
4. **알림 탭**. 텔레그램으로 나가는 알림을 앱 안에도 쌓을지. 쌓는다면 읽음
   처리 상태를 저장할 테이블이 하나 필요하다.

탭 5개(대시보드/전략/기록/알림/관리)와 상단 요약 카드 4개를 넣었다.

### 구현 중 잡은 것

리스크 정책을 대시보드와 관리 양쪽에 넣었더니 Streamlit이 **같은 키의 폼이
둘이라며 화면 전체를 죽였다.** 목업에서도 리스크 정책은 대시보드 목록에만
있으므로 관리에서 뺐다. 코드만 봤으면 못 잡았을 것이고, 실제로 브라우저로
띄웠기에 드러났다.

## 8. 목업 재적용 + 용어 해설 (2026-08-18 2차)

### 무엇이 바뀌었나

1차 구현은 탭 5개는 맞췄지만 각 줄이 밋밋한 expander라 목업의 카드 목록과
달랐다. 이번에 `section()` 헬퍼를 두어 **아이콘 · 굵은 제목 · 회색 부제 ·
오른쪽 뱃지**를 한 줄에 담았다.

목업의 카드에는 펼침 화살표가 달려 있다. Streamlit에서 그 동작을 그대로
주는 위젯은 expander뿐인데 라벨을 하나만 받으므로, 아이콘·부제·뱃지를
라벨 안에 마크다운으로 넣었다. CSS로 카드를 새로 그리면 Streamlit이 올라갈
때마다 조용히 깨지고, 그러면 **고쳐야 할 줄 모르는 채로** 망가진다.

### 대시보드 탭이 목업 순서대로 5줄

활성 전략 / 보유 종목 & 최근 주문 / 매매 기록 / 전략 리뷰 결과 / 리스크 정책.

목업은 '전략'·'기록'이 아래 탭에도 있는데 대시보드에도 같은 줄이 있다.
바로가기 허브 구조다. 다만 같은 입력 폼을 두 탭에 그대로 두면 Streamlit이
"같은 키의 폼이 둘"이라며 화면 전체를 죽인다(1차 때 실제로 죽였다). 그래서
**다른 탭에 본체가 있는 줄은 요약과 길안내만**, 본체가 여기뿐인 줄만 통째로
편다.

### 상단 카드 4번째를 바꿨다

목업은 '최근 동기화 12:41 · 방금 전'이다. 그런데 이 값은 늘 '방금 전'이라
아무것도 알려 주지 않는다. 정작 궁금한 건 **"엔진이 돌긴 돌았나"** 라서
`run_logs`의 마지막 실행(시각 · 신호 수 · 주문 수)으로 바꿨다. 매매가
0건인 날에도 뭔가 말해 주는 유일한 칸이다.

### 용어 해설

용어를 화면 문구에 흩어 놓으면 같은 말이 화면마다 다르게 설명된다.
`src/muwon/dashboard/glossary.py` 한 군데에 모으고, 항목마다 세 조각을 둔다.

- **뜻**. 그 말이 가리키는 것. 다른 전문용어를 쓰지 않는다.
- **어떻게 읽나**. 그 숫자를 봤을 때 무엇을 판단하면 되는가. 뜻만 알아도
  화면을 못 읽는 경우가 많아 판단 기준을 따로 뒀다.
- **영문**. 검색용. 한글로는 자료가 잘 안 나오는 말이 많다.

두 곳에서 쓴다. 화면 위쪽의 **전체 사전**(검색칸 포함)과, 각 줄 안의
**"이 화면에 나오는 말"**. 사전을 통째로 보여 주면 아무도 안 읽는다.
지금 보고 있는 표에 나오는 단어만 그 자리에서 풀어 줘야 읽힌다.

처음엔 표(`st.dataframe`)로 그렸다가 마크다운으로 바꿨다. 표는 설명이 한
줄을 넘으면 잘려서 정작 중요한 뒷말이 안 보였고, Streamlit 표는 캔버스로
그려져 브라우저 Ctrl+F가 안 먹는다. 사전인데 검색이 안 되면 곤란하다.

`docs/용어사전.md`로도 뽑는다(`scripts/export_glossary.py`). 대시보드를 안
켜고도 읽히게 하기 위해서다. 두 벌을 손으로 관리하면 반드시 어긋나므로
코드에서 뽑고, 어긋나면 테스트(`--check`)가 잡는다.

## 9. 매매 기준 · 실행 예정 (2026-08-18 3차)

화면에 전략 **이름**만 있었다. `volume_surge_5d`라는 이름은 그 전략이 무엇을
사는지 아무것도 말해 주지 않는다. 그리고 "이게 언제 또 도는지"도 알 수 없어서,
아무 일도 안 일어난 화면을 보고 **고장인지 아직 시간이 안 된 건지** 판단할 수
없었다.

### 매매 기준 (`strategy_rules.py`)

전략 객체의 **실제 파라미터**를 읽어서 문장을 만든다. registry의
`description`은 사람이 쓴 글이라 코드가 바뀌어도 그대로 남는다. 그런
어긋난 문서를 이 저장소에서도 여러 번 봤다.

화면은 셋으로 나눈다.

- 🟢 **이럴 때 삽니다**. 진입 조건, 실제 숫자가 박힌 채로
- 🔴 **이럴 때 팝니다**. 청산 조건
- ⚙️ **전략과 상관없이 항상 적용되는 규칙**. 유니버스 크기, 판단에 쓰는
  봉, 비중·손절·일일 한도·킬스위치

마지막 덩어리가 특히 중요하다. 전략만 봐서는 **"왜 신호가 났는데 안 샀지"**를
설명할 수 없다. 실제로는 이 규칙들이 먼저 걸러 낸다.

테스트가 두 가지를 못 박는다. 등록된 22개 전략이 **전부** 문장을 갖는지(새
전략에 설명을 안 붙이면 실패), 그리고 같은 전략 클래스에 다른 숫자를 넣었을 때
**문장이 따라 바뀌는지**(`2배·5거래일` → `3배·3거래일`). 뒤엣것이 없으면 설명이
슬그머니 상수로 굳는다.

### 실행 예정 (`schedule.py`)

**시각을 화면에 손으로 적지 않는다.** `.github/workflows`의 cron을 직접 읽어
계산한다. 스케줄을 바꿨는데 화면이 옛 시각을 말하면 그건 안내가 아니라
거짓말이다. 실제로 오늘 cron을 `30 6 * * 1-5`에서 `5 0 * * 1-5`로 바꿨다.

cron은 UTC라 한국시간으로 옮겨 보여 준다. `5 0 * * 1-5` → **평일 09:05**,
`0 15 * * 0` → **매주 월 00:00**(일요일 15:00 UTC가 한국에선 월요일이다).

두 군데에 둔다.

- 펼치지 않아도 보이는 **한 줄 배너.** "다음 자동매매: 08월 19일(수) 09:05 · 41분 뒤"
- **실행 예정** 줄: 전체 일정표

주의할 점 두 가지를 코드에 못 박았다. cron의 요일은 **일요일이 0**이고
파이썬 `weekday()`는 월요일이 0이라, 그대로 비교하면 하루씩 밀린다. 그리고
UTC→KST에서 자정을 넘기면 **요일도 하루 밀린다**. 둘 다 조용히 틀리는
종류라 테스트로 고정했다.

cron 라이브러리를 새로 들이지 않고 40줄로 직접 계산한다. 이 저장소가 쓰는
건 다섯 칸 기본 문법뿐이고, 잘못된 cron을 만나도 화면이 죽지 않게(그냥
`None`) 두는 편이 낫다고 봤다.

### 만들면서 고친 것

- `st.info`는 HTML을 안 그린다. `<small>`을 넣었더니 태그가 글자로 나왔다.
- `%a`는 `Wed`를 준다. 한국시간 안내에 영어 요일이 섞이면 읽는 리듬이 끊긴다.

## 10. 폰에서 보고 잡은 것 (2026-08-19)

데스크톱 폭으로만 보고 있었다. 폰 폭(390px)으로 렌더링해 보니 세 가지가
드러났다.

### 화면이 거짓말을 하고 있었다

자동 실행 일정을 꺼 놓은 상태인데 요약 카드는 **`LIVE`** 였다. 킬스위치
(`trading_enabled`)만 보고 판단했기 때문이다. 둘은 다른 것이다.

- **스케줄**(워크플로 cron): 아예 실행이 예약돼 있는가
- **킬스위치**. 실행되면 매수를 하는가

둘 중 하나라도 꺼져 있으면 자동매매는 일어나지 않는다. `automation_state()`가
둘을 합쳐 판단하고, 꺼져 있으면 화면 맨 위에 왜 꺼졌는지를 띄운다. 이 한
줄이 틀리면 "왜 아무 일도 안 일어나지"를 엉뚱한 데서 찾게 된다.

토글 이름도 바꿨다. `자동매매 활성화`는 켜져 있는데 바로 위에서 "자동 실행
꺼짐"이라고 하니 무엇이 켜진 건지 알 수 없었다. **`신규 매수 허용`** 으로
바꾸고, 이 스위치가 여닫는 것이 신규 매수뿐이라는 설명을 붙였다.

### 요약 카드가 잘렸다

가로 스크롤이라 폰에서 4개 중 2개만 보이고, 스크롤 가능하다는 표시도 없어
카드가 넷이라는 걸 알 수 없었다. `max-width: 640px`에서 2×2로 접는다.

### 제목이 화면 위쪽을 먹었다

`st.title("muwon406 대시보드")`가 폰에서 두 줄로 넘쳐 첫 화면의 3분의 1을
차지했다. 목업 제목(`자동매매 운영 대시보드`)으로 바꾸고 크기를 한 단계
낮췄다.

`상태 조회: 00:15:58`도 없앴다. 화면을 새로 그린 시각일 뿐인데 폰에서 한
줄을 통째로 먹으면서 아무것도 안 알려 줬다.
