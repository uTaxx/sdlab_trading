# 모의투자를 실행하기 전에 정해 둘 기준

*2026-08-20*

## 왜 한 군데에 모았나

기준이 코드·시트·대시보드·문서에 흩어져 있으면 **하나만 고치고 나머지를
잊는다.** 그래서 목록을 `src/muwon/settings/from_sheet.py`의 **기준표
하나**에만 적어 두고, 시트 초안·검증 규칙·대시보드 화면·텔레그램 명령·이
문서가 전부 그것을 읽는다.

기준을 새로 만들려면 거기 한 줄을 추가하면 되고, 그러면 나머지가 저절로
따라온다. 시험이 그걸 지킨다(`test_기준표와_시트초안이_어긋나지_않는다`).

## 고치는 길 셋: 전부 같은 곳을 본다

| 어디서 | 어떻게 | 언제 쓰나 |
|---|---|---|
| **구글 시트** | `설정` 탭에서 직접 | 여러 개를 한꺼번에 |
| **대시보드** | 관리 → 매매 기준 | 설명을 보면서 |
| **텔레그램** | `/설정 <이름> <값>` | 폰을 보고 있을 때 |

셋 다 **구글 시트에 쓴다.** 시트가 원본이고 코드는 읽기만 한다는 규칙을
깨지 않기 위해서다. 코드가 따로 기억하는 값이 생기면 시트를 봐도 지금
뭐가 걸려 있는지 알 수 없게 된다.

## 기준 목록

값은 시트에 사람이 읽는 단위(`15`, `-5`)로 적는다. 소수로 바꾸는 것과
범위를 보는 것은 읽는 자리에서 한다.

### 켜고 끄는 것

| 이름 | 기본 | 무엇 |
|---|---|---|
| `trading_enabled` | **false** | 킬스위치. false면 신규 매수를 전부 거부 |
| `require_approval` | true | 매수 전에 사람이 승인한 것만 산다 |

**킬스위치는 시트와 대시보드가 둘 다 켜져야 켜진다.** 한 쪽만 꺼도 꺼진다.
그리고 **텔레그램으로는 켤 수 없다**. 끄는 것만 된다. 폰에서 손가락이
미끄러져 매매가 켜지면 안 된다.

### 얼마나 걸 것인가

| 이름 | 기본 | 무엇 |
|---|---|---|
| `max_position_weight` | 15% | 한 종목에 자금의 몇 %까지 |
| `max_concurrent_positions` | 8 | 동시에 몇 종목까지 |
| `max_per_sector` | 2 | 한 섹터에서 몇 종목까지 |

**둘을 곱하면 100%를 넘으면 안 된다.** 15% × 8 = 120%인데 현금은 100%뿐
이라, 뒤쪽 종목은 신호가 나도 거부된다. 로그에는 이유가 "리스크 매니저
거부"로만 남아 왜인지 알기 어렵다. `기준 제안` 워크플로가 이걸 잡아낸다.

`max_per_sector`는 **예측이 아니라 제약**이다. 신호 난 것을 그냥 사면 어떤
날 반도체 다섯 종목이 한꺼번에 잡히는데, 그건 분산이 아니라 반도체 하나에
다섯 배로 건 것이다.

### 언제 팔 것인가

| 이름 | 기본 | 무엇 |
|---|---|---|
| `stop_loss_pct` | −5% | 이만큼 빠지면 손절 |
| `daily_loss_limit_pct` | −3% | 하루에 이만큼 잃으면 그날 신규 매수 중단 |
| `take_profit_pct` | **0 (끔)** | 이만큼 오르면 판다 |

**익절이 0인 것은 "안 재 봤다"가 아니라 "재 보고 뺐다"는 뜻이다.** 붙였을
때 나아지는지 쟀고 기각됐다. 오르는 중에 팔면 큰 수익을 놓친다.

손절선 −5%는 **아직 근거가 없다.** 실거래 매매가 0건이라 실제 체결이
어떻게 되는지 아무도 본 적이 없다. 모의투자를 실행해야 정할 수 있다.

### 무엇을 살 것인가

| 이름 | 기본 | 무엇 |
|---|---|---|
| `min_turnover_eok` | 50억 | 최근 20일 평균 거래대금이 이보다 적으면 안 산다 |
| `sector_filter_enabled` | **false** | 강도 상위 섹터의 종목만 살까 |
| `sector_lookback` | 20일 | 섹터 강도를 며칠로 잴까 |
| `sector_top_n` | 3 | 1차에서 몇 섹터를 고를까 |

`sector_filter_enabled`가 기본 꺼짐인 이유는 **근거가 없어서**다
(`docs/섹터선정_검증.md`). 여섯 조합 전부 우연 폭 안이었고 여덟 해 중
다섯 해가 마이너스였다. 순위는 켜든 끄든 화면에 보여 준다. 끄는 것은
그걸 근거로 사고파는 것이지 보는 것이 아니다.

`sector_lookback` 기본값을 20일로 둔 것도 같은 이유다. 검증에서 120일이
조금 나았지만 그 차이가 우연과 구별되지 않는다. **제일 좋아 보이는 값을
고르는 것이 곧 과최적화다.**

## 제안은 근거가 있을 때만 한다

`기준 제안` 워크플로(주 1회 + 손으로)가 텔레그램으로 제안을 보낸다.
제안하는 것은 두 종류뿐이다.

- **산수로 확인되는 것**. 비중 × 동시보유 > 100%, 닿을 수 없는 동시보유 수
- **세어 보면 나오는 것**. 유니버스 중 몇이 거래대금 최소 기준에 걸리나

손절선을 얼마로 할지, 익절을 켤지 같은 것은 **표본이 쌓여야** 말할 수 있다.
그때까지는 "모른다"고 말한다. 없는 근거를 지어내는 것보다 낫다.

제안에는 그대로 붙여 넣을 명령이 같이 온다:

```
[권함] 동시 보유 종목 수 8 → 6
    한 종목 15% × 8종목 = 120%인데 현금은 100%입니다...
    바꾸려면: /설정 max_concurrent_positions 6
```

## 텔레그램으로 무엇을 할 수 있나

```
/상태              지금 걸려 있는 기준 전부
/설정 <이름> <값>   기준 하나 바꾸기
/끄기              매매 즉시 중단 (언제든)
/승인 005930       오늘 후보 중 이 종목을 사도 좋다
/도움              명령 목록
```

### 승인은 버튼으로 한다

매수 후보 알림에 **✅ 승인 / ❌ 거절 버튼**이 붙어 온다.

```
📋 2026-08-20 매수 후보 2종목

  [반도체] HPSP(403870) @ 45,700원
     거래량 2배 급증 + 7.2% 상승
  ...

  [ ✅ HPSP ]        [ ❌ ]
  [ ✅ 삼성전자 ]     [ ❌ ]
  [ ✅ 전부 승인 ]    [ ❌ 전부 거절 ]
```

종목코드 여섯 자리를 폰에서 정확히 치는 일은 생각보다 귀찮고, **귀찮으면
안 하게 되고, 안 하면 승인 스텝이 없는 것과 같다.** 버튼은 한 번 누르면
끝이고 무엇을 누르는지 이름으로 보인다. 코드를 잘못 치면 엉뚱한 종목을
승인하지만 버튼은 그럴 수가 없다.

**누르면 판이 바뀐다.** `✅ HPSP` → `☑️ HPSP 승인함`. 화면이 지금 상태를
보여 주지 않으면 방금 누른 게 먹었는지 몰라서 또 누르게 된다.

**되돌릴 수 있다.** 잘못 눌렀으면 반대쪽을 누르면 된다. 아직 사기 전이라
승인은 되돌릴 수 없는 일이 아니다.

**거절도 기록한다.** 빈 칸으로 두는 것과 매매 결과는 같지만, 나중에
**"안 봤다"와 "보고 거절했다"는 전혀 다른 이야기**다. 앞의 것은 알림이 안
갔거나 놓친 것이고, 뒤의 것은 판단이다. 구별해 두지 않으면 승인 스텝이
실제로 쓰이고 있는지 알 수가 없다.

**버튼으로 되는 일의 범위는 좁다.** 오늘 제안된 종목의 승인/거절만 된다.
매매를 켜거나 기준을 바꾸는 버튼은 만들지 않았다. 폰 화면에서 손가락이
스치는 일이 실제로 일어나고, 그 결과가 '매매 켜짐'이면 안 된다.

**어제 버튼은 안 먹는다.** 지난 목록의 버튼을 누르면 "이제 못 씁니다"라고
답하고 아무것도 바꾸지 않는다.

**받는 방식**: 봇에 웹훅을 걸지 않는다. 그러려면 상시 도는 서버가 필요한데
이 저장소에는 그런 게 없다. 대신 워크플로가 장중에 10분마다 `getUpdates`로
물어보러 간다. 늦어야 몇 분이고, 설정을 바꾸는 일에 몇 분은 늦어도 된다.

**안전 규칙**

- 저장된 `chat_id`에서 온 것만 듣는다. 봇 이름은 누구나 알 수 있다
- **매매를 켜는 것은 여기서 못 한다.** 끄는 것만 된다
- 값 검증은 시트에서 읽을 때와 **같은 규칙**을 쓴다. 규칙이 두 벌이면
  한쪽으로 들어온 값이 다른 쪽 기준을 어긴다
- 모르는 말에는 안내만 한다. "아마 이 뜻이겠지"가 매매 기준을 바꾸면 안 된다
- 같은 명령을 두 번 실행하지 않는다. 어디까지 읽었는지를 DB에 남긴다

## 아직 안 정한 것

- **손절선·익절선의 근거**. 모의투자 표본이 필요하다
- **섹터 상한이 성적을 얼마나 바꾸는지**. 백테스트 엔진에 섹터 개념이 없다
- **한 번에 얼마씩 살지(수량)**. 지금은 매수 단계에서 그때 현금으로 정한다
