# 대시보드 개선안 (2026-09-07)

`docs/시스템_설명서.md`를 읽고, 화면을 브라우저(PC 폭 1280px, 폰 폭 390px)로
직접 열어 탭 일곱 개의 글을 전부 뽑아 본 뒤에 적은 것입니다. 어휘 문제는
이날 바로 고쳤고(§5), 구조 문제는 여기에 제안으로만 남깁니다.

## 1. 결론

지금 화면은 **기능 단위로 묶여 있고, 사용자가 하루 동안 실제로 하는 일의
순서와는 어긋나는 자리가 다섯 곳** 있습니다.

1. 아침에 승인할 때 판단 근거(왜 이 종목인지, 어제 종가와 지금 가격의 차이)가
   승인 화면에 없습니다.
2. 전략을 고르는 자리와 예약하는 자리가 다른 탭에 있습니다.
3. '주간 전략 선택' 탭 하나에 다섯 단계 안내, 판단 지침 검증, 구간별 순위,
   그림자 추적, 변경 이력, 백테스트 넷, 연도 격자, 보유 상한별 비교가 전부
   들어 있어서 폰 폭에서 세로 길이가 17,876px입니다. 한 화면의 45배입니다.
4. 같은 설정값을 두 이름으로 부릅니다. 설정 탭의 입력 칸 이름과 변경 이력의
   항목 이름이 다릅니다.
5. 다섯 단계 중 2단계(비슷했던 과거 찾기)가 "아직 계산하지 않습니다"라고
   적힌 채로 매일 보입니다.

아래는 사용자가 실제로 밟는 순서대로 본 것입니다.

## 2. 단계별로 본 것

### 0단계. 처음 열기 (인증 키 입력)

지금은 문제가 없습니다. 인증 키 화면 하나만 뜨고, 어디서 키를 받는지도
적혀 있습니다.

제안은 하나입니다. 키를 넣은 뒤 n8n 연결에 실패하면 현재 손익 탭은 빨간
오류 상자를 띄우고, 나머지 탭은 조용히 "예시 데이터입니다"만 붙입니다.
같은 상태를 탭마다 다르게 보여 주는 것입니다. 연결 실패는 한 곳(화면 맨
위)에서 한 번 알리고, 각 탭은 예시 표시만 남기는 쪽이 읽기 쉽습니다.

### 1단계. 아침 08:30~09:05, 매수 후보 승인 (매수 승인 탭)

하루 중 실제 주문에 영향을 주는 유일한 결정인데, 결정에 필요한 자료가 그
화면에 없습니다.

| 지금 보이는 것 | 없는 것 |
|---|---|
| 종목명, 코드, 섹터, 전략 이름, 수량 × 예상가 | 왜 이 종목이 후보인지 (신호 근거 한 줄) |
| 승인 / 제외 버튼 | 어제 종가 대비 지금 가격 (갭). 5% 넘으면 09:05에 안 삽니다 |
| | 승인 마감까지 남은 시간 (09:05) |
| | 오늘 전략이 바뀌었는지. 텔레그램 알림에는 이 줄이 있는데 화면에는 없습니다 |
| | 08:30 실행이 실패했는지. 후보 0개가 "신호 없음"인지 "실행 실패"인지 구별이 안 됩니다 |

특히 마지막 줄이 중요합니다. 후보가 0개인 날 화면은 "매수 조건을 충족한
종목이 없었습니다"라고 단정합니다. 설명서 4-2에 적힌 대로 미국 ETF 시세를
못 받은 날도 후보가 0개인데, 그날도 같은 문장이 나옵니다.

같은 탭 아래에 있는 '승인 결정 되짚기'는 아침에 볼 자료가 아닙니다. 지난
승인의 결과를 보는 것이라 저녁에 볼 자료입니다. 거래 기록 탭으로 옮기는
쪽이 맞습니다.

### 2단계. 장중, 손익과 손절 확인 (현재 손익 탭)

큰 문제는 없습니다. 킬스위치가 화면 위에 늘 보이는 것도 맞습니다.

제안 둘입니다.

- 손절 감시가 마지막으로 실행된 시각이 없습니다. 09-02에 11:20부터 13:00까지
  감시가 멈춘 적이 있는데, 화면에서는 알 방법이 없었습니다. 보유 종목 표
  위에 "손절 감시 마지막 실행 HH:MM" 한 줄을 둡니다.
- 보유 종목 표에 손절선과 보유 상한까지 남은 거래일을 같이 적습니다. 지금은
  현재가와 수익률만 있어서, -5% 손절에 얼마나 가까운지 계산해야 합니다.

### 3단계. 저녁, 기록 확인 (거래 기록 탭)

- 보유기간 칸이 늘 비어 있습니다. 설명서 4-2에도 적혀 있는 결함입니다. 비어
  있는 칸은 표에서 빼거나 채워야 합니다.
- 실행 기록의 '분석 대상' 칸이 숫자만 있습니다(예: 45). 종목 수인지 신호
  수인지 이름으로는 알 수 없습니다.

### 4단계. 저녁 17:50 이후, 전략 검토와 선택 (주간 전략 선택 탭)

이 탭이 가장 불편합니다.

**하나, 너무 깁니다.** 폰 폭에서 17,876px입니다. 접힌 부분을 다 펼친 값이긴
하지만, 접힌 제목만 세어도 열 개가 넘습니다. 사용자가 이 탭에서 하는 일은
"오늘 전략을 바꿀 이유가 있나"를 보는 것 하나입니다. 그 답과 무관한 것은
다른 탭으로 보내야 합니다.

| 지금 이 탭에 있는 것 | 제안 |
|---|---|
| 전략을 고르는 다섯 단계 안내 | 남김 |
| 판단 지침 검증 | '근거 자료' 탭으로 |
| 매매 대상 종목 트렌드 | 시장 트렌드 탭으로 |
| 구간별 전략 순위, 검토 이력, 결과 해석 | 남김. 이 탭의 본체 |
| 전략 변경 절차 | 남김 |
| 지난 후보를 다시 계산한 결과 (그림자 추적) | 남김 |
| 전략 변경 이력 | 설정 탭의 변경 이력과 합침 |
| 백테스트 (현재 전략, 이전 결과, 선택 전략, 연도 격자, 해석 가이드) | '근거 자료' 탭으로 |
| 보유 상한별 전략 비교 | '근거 자료' 탭으로 |

**둘, 고르는 자리와 예약하는 자리가 다릅니다.** 안내 4단계는 "텔레그램 또는
이 화면에서 예약합니다"라고 적혀 있는데, 예약 버튼은 이 탭에 없고 설정
탭의 세부 전략 칸에 있습니다. 순위표 바로 아래에 "이 전략으로 변경 예약"
버튼을 두어야 합니다. 설정 탭의 버튼은 그대로 두어도 됩니다.

**셋, 2단계가 빈 채로 매일 보입니다.** "최근 구간과 비슷했던 과거를
찾습니다. 아직 계산하지 않습니다"가 번호 붙은 단계로 나옵니다. 설명서
4-1에 적힌 대로 코드는 있고 연결만 안 된 상태입니다. 연결하기 전까지는
단계 번호에서 빼고 "준비 중" 표시로 내리는 쪽이 낫습니다. 매일 보는
"아직"은 고장으로 읽힙니다.

**넷, 판단 지침 검증의 결론과 행동할 자리가 떨어져 있습니다.** 검증 결과는
"20영업일에서 구간 최대낙폭 중앙값이 지금 지침보다 낫다"고 적는데, 지침을
바꾸는 칸은 설정 탭(연 단위 지침)과 보유 상한별 비교 구역(구간 지침) 두
곳에 따로 있습니다. 지침이 두 벌이라는 것 자체도 설명이 없습니다. 검증
결과 바로 옆에 "이 지침으로 바꾸기"가 있어야 하고, 두 벌인 까닭을 한
문장으로 적어야 합니다.

**다섯, 구간 이름이 탭 안에서 세 가지입니다.** 전략 검토는 1주·1개월·3개월,
기간 검증은 3개월·12개월·5년, 보유 상한별 비교는 3~20영업일입니다. 화면
어디에도 왜 다른지 적혀 있지 않습니다. 각 표 머리에 "이 표는 ~을 보는
것이라 구간이 ~입니다" 한 줄이 필요합니다.

### 5단계. 설정 바꾸기 (설정 탭)

**같은 값에 이름이 둘입니다.** 설정 탭 입력 칸의 이름과, 시트·변경 이력·
텔레그램이 쓰는 이름(`기준설명.json`)이 다릅니다.

| 설정 탭 입력 칸 | 변경 이력·시트·알림 |
|---|---|
| 종목당 최대 투자비중 (%) | 한 종목 최대 비중 |
| 최대 동시 보유 종목 수 | 동시 보유 종목 수 |
| 섹터당 최대 보유 종목 수 | 섹터당 종목 수 |
| 최소 평균 거래대금 (억원) | 거래대금 최소 기준(억) |
| 일일 손실 제한 (%) | 하루 손실 한도 |
| 손절 기준 (%) | 손절선 |
| 익절 기준 (%) | 익절선 |
| 최대 보유기간 (거래일) | 보유 기간 상한(일) |

변경 이력에서 "한 종목 최대 비중 15 → 10"을 보고 설정 탭에서 그 칸을
찾으면 이름이 다릅니다. 입력 칸 이름을 `기준설명.json`의 이름으로 맞추면
원본이 하나가 됩니다.

**판단 지침이 설정 탭 맨 위에 있습니다.** 이 값은 주문에 영향을 주지 않고
전략 검토의 순위만 바꿉니다. 매수·매도 기준보다 위에 있을 이유가 없습니다.
주간 전략 선택 탭으로 옮기거나 설정 탭 맨 아래로 내립니다.

**"예시 자료" 상태에서 입력 칸이 기본값으로 채워집니다.** 경고문은 있지만
칸에 숫자가 들어 있어서 실제 설정으로 읽힙니다. 연결이 안 됐을 때는 칸을
비우고 빈 값으로 두는 쪽이 안전합니다.

### 6단계. 용어 안내 탭

113개 항목 중 앞쪽 50여 개가 반말("~다")이고 뒤쪽이 존댓말이었습니다.
이날 전부 존댓말로 맞췄습니다(§5). 남은 제안은 하나입니다. 개발 쪽
용어(기록 고유 번호, 안전한 쪽으로 실패, 기준 제안)와 매매 용어를 묶음으로
나누면 찾기 쉽습니다.

## 3. 화면 글과 실제 동작이 어긋났던 것 (이날 고침)

설명서 5부 2번이 부탁한 것입니다. 렌더링한 글을 코드와 대조해 찾았습니다.

| 화면에 적혀 있던 것 | 실제 | 고친 것 |
|---|---|---|
| 세부 전략은 "이 화면에서는 조회만 가능합니다" | 09-04부터 화면에서 예약할 수 있음 | "변경을 예약만 할 수 있고, 다음 거래일 08:20에 반영됩니다" |
| 08:20 줄 "승인하고 확정한 전략 변경" | 09-01에 확정 단계를 없앴음. 한 번 누르면 예약 | "예약한 전략 변경" |
| "승인은 '오늘 승인' 탭에서" (두 곳) | 탭 이름은 '매수 승인' | '매수 승인' 탭 |
| "전략 및 설정 탭에서 예약" | 탭 이름은 '설정' | 설정 탭 |
| 판단 지침 검증 대조군 줄에 `volume_surge_3d_us60_2` | 전략 키가 그대로 노출 | "바꾸지 않고 거래량 급증 3일 + 미국 섹터 유지" |
| 용어 안내 '국면': "내리는 판(BEAR)에서는 매수 기준을 확 높여 사실상 안 산다" | 시장 국면으로 매매를 켜고 끄지 않음 (설계안 §43·§46·§47) | 국면은 성과를 나눠 볼 때만 쓴다고 고침 |
| 용어 안내 '유니버스': "8섹터 50종목", "시가총액 상위 60종목" | 39종목 9섹터, 30종목 | 바뀌는 숫자를 글에서 뺌 |
| 용어 안내 '승인 스텝': "시트 승인대기 탭의 승인 칸에서 처리" | 텔레그램 버튼과 화면에서 처리 | 고침 |
| 용어 안내 '익절': "현재 해제되어 있다(0%)" | 0은 끔이 아니라 전략에 맡김 (09-02에 뜻이 바뀜) | 고침 |

## 4. 어긋난 것 중 아직 안 고친 것

- 기간 검증 결과 밑의 "익절 끔 · 보유 전략이 정한 대로"는 텔레그램 알림과
  테스트 두 곳이 같은 문장을 쓰고 있어서 이번에 손대지 않았습니다. CLAUDE.md
  기준으로는 "켜짐/꺼짐" 대신 "동작 중/중지"를 써야 하는 자리입니다.
- 설정 탭 입력 칸 이름과 `기준설명.json` 이름의 불일치(§2의 5단계 표)는
  이름을 어느 쪽으로 맞출지 정해야 해서 남겼습니다.

## 5. 이날 고친 어휘

화면에 실제로 그려진 글을 뽑아 CLAUDE.md의 표와 대조했습니다. 고친 원본은
`index.html`, `app.js`, 그리고 자료 JSON의 원본인 파이썬 다섯 파일입니다.

| 있던 말 | 고친 말 | 자리 |
|---|---|---|
| 과거 시세로 돌려 본 결과 | 과거 시세로 계산한 백테스트 결과 | 근거 접이 제목 |
| 보유 상한을 바꿔 가며 잰 결과 | 보유 상한별 비교 결과 | 근거 접이 제목 |
| 전략을 줄 세우는 기준 | 전략의 순위를 매기는 기준 | 판단 지침 검증 |
| 갈린다는 사실 자체가 정보 | 1위가 서로 다르다는 사실 자체가 정보 | 구간별 순위 |
| 지금 걸린 값 | 지금 설정된 값 | 설정 탭 경고 |
| 연결 주소와 열쇠 | 연결 주소와 인증 키 | 전략 예약 안내 |
| 이 정도 차이는 같다고 본다는 폭 / 같다고 보는 차이 | 동점 범위 | 판단 지침 |
| 그대로 둡니다 | 현재 지침 유지 | 지침 검증 표시·총평 |
| 무작위로 고름 (200번의 가운데값) | 무작위로 고른 경우 (200회 중앙값) | 지침 검증 대조군 |
| 앞 12구간을 돌아봅니다 | 판정마다 직전 12구간을 봅니다 | 지침 검증 |
| 그 주에 걸린 한두 종목, 방금 건 것이 돌기는 하는지 | 그 주에 매수한 한두 종목, 방금 설정한 전략이 실행되는지 | 기간 설명 |
| 훑어보는 용도 | 확인하는 용도 | 기간 설명 |
