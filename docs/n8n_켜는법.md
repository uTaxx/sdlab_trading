# 1부. GitHub 열쇠 만들기 (5분)

n8n이 GitHub를 부르려면 열쇠가 필요합니다. **제일 좁은 열쇠**를 만듭니다.

### 1-1. 발급 화면으로

1. https://github.com 에 로그인
2. 오른쪽 위 **프로필 사진** → **Settings**
3. 왼쪽 맨 아래 **Developer settings**
4. **Personal access tokens** → **Fine-grained tokens**
5. **Generate new token** 단추

> 두 종류가 있습니다. **Fine-grained**(세밀한 것)를 고르세요. 옛날
> 방식(Tokens classic)은 권한을 좁게 못 줍니다.

### 1-2. 이렇게 채웁니다

| 칸 | 넣을 것 |
|---|---|
| **Token name** | `n8n muwon406` |
| **Expiration** | 90일 정도 (지나면 다시 만들어야 합니다) |
| **Repository access** | **Only select repositories** → `uTaxx/sdlab_trading` 하나만 |

그다음 **Repository permissions**를 펼치고 **`Actions`** 항목을 찾아
**`Read and write`**로 바꿉니다.

> **`Actions` 하나만입니다.** `Contents`는 건드리지 마세요 — 그건 저장소
> 코드를 바꿀 수 있는 권한이고, n8n에는 그럴 이유가 없습니다.
>
> `Metadata: Read-only`는 저절로 켜집니다. 정상입니다.

### 1-3. 만들고 복사

**Generate token** → `github_pat_...`로 시작하는 긴 글자가 나옵니다.

⚠️ **이 화면을 벗어나면 다시 못 봅니다.** 바로 다음 단계로 가서 붙여넣으세요.
⚠️ **채팅창에 붙여넣지 마세요.** n8n 칸에만 넣습니다.

# 2부. 시계 켜기 (10분)

### 2-1. 워크플로 열기

https://sondullab.app.n8n.cloud/workflow/t2t8DmJ9d7yB4g4U

트리거 넷과 HTTP 넷이 짝지어 있는 것이 보입니다.

### 2-2. 첫 노드에 열쇠 넣기

1. **`시장·섹터 리포트 부르기`** 를 두 번 누릅니다
2. 맨 위 **Credential to connect with** 칸에서 **Create new credential**
3. 창이 뜨면 두 칸을 채웁니다

| 칸 | 넣을 것 |
|---|---|
| **Authentication Template** | 아래 한 줄을 그대로 붙여넣기 |
| **api_key** (또는 Value) | 1부에서 복사한 `github_pat_...` |

Authentication Template에 넣을 것:

```json
{"headers":{"Authorization":"Bearer {{api_key}}"}}
```

4. 이름을 **`무원406 깃허브 PAT (Actions 쓰기)`** 로 바꾸고 **Save**

> 이게 하는 일: GitHub에 요청을 보낼 때마다 `Authorization: Bearer <열쇠>`
> 라는 표를 같이 낸다는 뜻입니다. 열쇠는 n8n이 가려서 보관하고, 노드
> 화면에는 안 보입니다.

### 2-3. 나머지 셋에도 같은 열쇠

`매수 후보 제안 부르기`, `30분봉 수집 부르기`, `기록을 시트로 부르기`를
차례로 열고, Credential 칸에서 **방금 만든 것을 목록에서 고릅니다.**
(새로 만들지 마세요. 하나를 넷이 같이 씁니다.)

### 2-4. 진짜 되는지 시험

1. `시장·섹터 리포트 부르기` 노드를 열고 **Test step** 을 누릅니다
2. 초록색으로 끝나면 성공입니다

**GitHub에서도 확인하세요**:
https://github.com/uTaxx/sdlab_trading/actions — `시장·섹터 리포트`가 방금
돌기 시작했으면 열쇠가 제대로 된 겁니다.

| 나오는 말 | 뜻 | 할 일 |
|---|---|---|
| `401` | 열쇠가 틀렸다 | 1부를 다시 |
| `403` | 권한이 모자란다 | `Actions: Read and write` 확인 |
| `404` | 저장소나 워크플로 이름이 틀렸다 | 저장소를 `uTaxx/sdlab_trading`으로 골랐는지 |
| `422` | 몸통이 틀렸다 | `ref`가 `main`인지 |

### 2-5. 켜기

오른쪽 위 **Inactive** 스위치를 눌러 **Active**로 바꿉니다.

이제 평일마다 저절로 돕니다.

| 시각(한국) | 부르는 것 |
|---|---|
| 08:30 | 매수 후보 제안 (텔레그램으로 옵니다) |
| 09:05 | 승인된 것만 매수 |
| 15:40 | 30분봉 수집 |
| 17:30 | 장 마감 정산 (그날 주문을 최종 체결로 바로잡습니다) |
| 17:40 | 기록을 시트로 |
| **20:00** | 시장·섹터 리포트 |

> 리포트가 아침이 아니라 **그날 저녁**인 이유: 리포트는 마지막으로 완성된
> 일봉을 기준으로 삼습니다. 다음 날 아침에 봐도 내용은 전날 종가 기준이라
> **같은 내용을 12시간 늦게 받는 셈**이었습니다. 저녁에 받으면 자기 전에
> 읽고, 다음 날 08:30 후보를 볼 때 이미 장 상태를 알고 봅니다.

> 시간대는 **Asia/Seoul**로 못 박아 뒀습니다. 건드리지 마세요.

# 3부. 텔레그램 켜기 (15분) — **순서가 중요합니다**

## ⚠️ 먼저 읽어 주세요

이 워크플로를 만들 때 **n8n이 `Telegram account_LCIP`을 자동으로
붙였습니다.** 뉴스 시스템 봇입니다.

**그대로 켜면 그 봇의 웹훅을 빼앗아 뉴스 워크플로가 통째로 멈춥니다.**
한 봇을 두 곳에서 받을 수 없기 때문입니다.

그래서 **텔레그램 노드 두 개를 꺼 뒀습니다.** 꺼져 있으면 활성화해도
웹훅이 안 걸립니다. **자격증명을 바꾸기 전에는 켜지 마세요.**

### 3-1. 무원406 봇 토큰 찾기

텔레그램에서 **@BotFather** 와 대화:

1. `/mybots` 를 보냅니다
2. 목록에서 **무원406에 쓰는 봇**을 고릅니다
3. **API Token** 을 누르면 `1234567890:AA...` 형태가 나옵니다

> 뉴스 시스템 봇과 헷갈리지 마세요. 오늘 매수 후보 알림을 보낸 그 봇입니다.
> 확실치 않으면, 그 봇과의 대화창을 열어 이름을 확인한 뒤 고르세요.

### 3-2. 내 chat ID 찾기 (건너뛰어도 됩니다)

텔레그램에서 **@userinfobot** 에게 아무 말이나 보내면 `Id: 123456789`
처럼 답합니다. 그 숫자입니다.

> **모르겠으면 비워 두셔도 됩니다.** 저장소 쪽 코드가 어차피 저장된
> chat ID에서 온 것만 듣습니다. 여기 넣는 건 한 겹 더 두는 것뿐입니다.

### 3-3. 자격증명 바꾸기 — **여기가 핵심입니다**

https://sondullab.app.n8n.cloud/workflow/7tSSThvQIsLiIsLk

1. **`텔레그램에서 온 것`** 노드를 두 번 누릅니다
   (회색으로 꺼져 있습니다. 정상입니다)
2. Credential 칸에 **`Telegram account_LCIP`** 이 들어 있습니다 → **바꿉니다**
3. **Create new credential** → **Access Token** 칸에 3-1의 봇 토큰
4. 이름을 **`무원406 텔레그램 봇`** 으로 하고 **Save**
5. (chat ID를 아신다면) **Chat IDs** 칸에 3-2의 숫자
6. **`받았습니다 답하기`** 노드도 열어 **같은 자격증명을 목록에서 고릅니다**

> ⚠️ 6번을 빠뜨리면 그 노드만 뉴스 봇으로 답을 보냅니다.

### 3-4. 꺼 둔 노드 켜기

두 노드를 각각 **오른쪽 눌러 → Activate**(또는 노드 위 스위치)로 켭니다.
회색이 아니라 제 색으로 바뀌면 된 겁니다.

**이 순서를 지키세요**: 자격증명을 바꾼 **뒤에** 켭니다. 반대로 하면
뉴스 봇에 웹훅이 걸립니다.

### 3-5. GitHub 열쇠 넣기

**`깃허브로 넘기기`** 노드를 열고, Credential 칸에서 2-2에서 만든
**`무원406 깃허브 PAT (Actions 쓰기)`** 를 고릅니다.

### 3-6. 켜기

오른쪽 위 **Inactive** → **Active**.

이 순간 봇에 웹훅이 걸립니다.

### 3-7. 확인

1. 텔레그램에서 봇에게 **`/상태`** 를 보냅니다
2. 몇십 초 안에 지금 걸려 있는 기준이 답으로 옵니다

안 오면:
- n8n → 왼쪽 **Executions** 에서 그 워크플로가 돌았는지
- GitHub Actions에서 `텔레그램 (n8n이 넘겨준 것)` 이 돌았는지

### 3-8. 마무리 — 옛 방식 끄기

이제 GitHub 쪽 폴링은 아무것도 못 받습니다(한 봇을 두 곳에서 못 받으니까).
**말씀만 주시면 제가 `텔레그램 명령 받기`의 자동 실행을 꺼 드리겠습니다.**

안 꺼도 사고는 안 납니다 — 웹훅을 감지하면 스스로 물러나게 해 뒀습니다.
다만 10분마다 헛도는 실행이 쌓입니다.

# 되돌리는 법

**텔레그램 워크플로를 Inactive로 바꾸면** 웹훅이 풀리고 옛 방식이 다시
먹습니다. 그것만으로 원래대로 돌아갑니다.

웹훅이 안 풀리면 브라우저 주소창에 이걸 넣습니다(봇 토큰을 바꿔서):

```
https://api.telegram.org/bot<봇토큰>/deleteWebhook
```

**GitHub 열쇠를 없애려면** 발급했던 화면에서 Delete 하면 됩니다. 그러면
n8n이 GitHub를 못 부르고, 그게 전부입니다.

# 자주 걸리는 것

**"n8n에서는 성공인데 GitHub에서 아무 일도 안 일어난다"**
→ `ref` 가 `main`인지 보세요. 다른 가지 이름을 넣으면
   GitHub가 성공으로 답하고 아무것도 안 합니다.

**"자격증명을 고쳤는데도 웹훅이 안 걸린다"**
→ **n8n은 Publish 하는 순간에만 웹훅을 등록합니다.** 켜진 상태에서 봇
   토큰만 바꾸면 다시 등록하지 않습니다. **Unpublish 했다가 다시 Publish**
   하세요. 실제로 이것 때문에 한참 헤맸습니다 — 토큰이 틀린 줄 알았는데
   토큰은 맞았고 등록이 안 된 것이었습니다.

**"버튼을 눌러도 반응이 없다"**
→ `텔레그램에서 온 것` 노드의 Updates에 **`callback_query`가 켜져 있는지**
   보세요. 빠져 있으면 버튼 누름이 도착하는 즉시 버려집니다. 그리고 그
   사실이 어디에도 안 나타납니다.

**"뉴스 시스템이 멈췄다"**
→ 3-3을 건너뛰고 켠 경우입니다. 이 워크플로를 Inactive로 바꾸고, 뉴스
   워크플로를 껐다 켜면 그쪽 웹훅이 다시 걸립니다.
